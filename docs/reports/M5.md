# M5: full-model conversion, evaluation, final report

Status: **code complete for the gated stages; nothing has run on the full model.** Every
full-model stage needs hardware this container does not have (about 510 GB of source weights, more
than 15 GB of RAM, GPUs), and the download, the conversion and any QAT are gated on Vedant. This
report lists what is built and how it was tested, what each stage needs, and what is not built or
not run. It will hold the results tables once the runs are approved and done.

The "close to baseline" threshold for Mode C k = 2 (WikiText-2 perplexity within +3 %, lm-eval
tasks within 1.5 points) is **still a proposal**. It must be confirmed by Vedant before any eval
runs, and it will not be changed after results are seen.

### Server

`boilerplate serve CKPT --port 8000` serves `/v1/completions` and `/v1/chat/completions`, with
`"stream": true` as server-sent events ending in `data: [DONE]`, plus `/v1/models`, `/health`
and `/stats` (expert-cache hit rates and the Mode B cache size). It supports `max_tokens`,
`temperature`, `seed`, `stop`, `n` and `echo`, and the checkpoint's `chat_template`. It rejects
non-neutral `top_p` and penalties instead of ignoring them. Requests run one at a time, because
the engines are not thread safe. The `n` choices of one request are batched; continuous
batching across requests is not built.

### lm-eval adapter

`Scorer` needs only `engine.trace(ids).logits` and the tokenizer, so the same code scores every
engine and mode. It follows the harness conventions: context/continuation split at the
context's token count, trailing whitespace moved into the continuation, an empty context
prefixed with BOS (or EOS), left truncation, rolling windows with maximal context. On a tiny Llama
its scores match `transformers` to 1e-4. Requests are scored one sequence at a time.

## Not built

* **Mode D for V4.1.** The QAT trainer drives Hugging Face models (Llama, OLMoE). V4.1 does not
  run in `transformers`, and the Boilerplate engine is inference only. A trainable V4.1 graph
  (FP8/FP4 master handling, hyper-connections, engram, compressed attention) with expert
  parallelism is a project of its own. Per the standing rule it is not started until Vedant
  decides, after the OLMoE result. M4 is the evidence for what Mode D would cost in quality, and
  it is still untested.
* Expert parallelism and multi-GPU placement of V4.1's 384 experts per layer. The expert cache
  bounds memory on one device; it does not split work across devices.
* Continuous batching in the server, and batched scoring in the lm-eval adapter.
* BF16 activations in the CUDA ternary kernel (int8 only; BF16 uses the dequantized fallback).
* A GPU path for the V4.1 engine. Llama/OLMoE have one since 2026-11-06 (`device="cuda"`); V4.1
  still runs its FP8/FP4 torch kernels on CPU only.

## Not run (all of §7's measurements)

Per-layer cosine against the official reference on the full model; Mode B bit-identity on
≥ 1,024 tokens; WikiText-2 and C4 perplexity; MMLU, GSM8K, HumanEval; routing drift; file bytes;
peak RAM/VRAM; prefill and decode tok/s. Reason for each: the full model has not been
downloaded or converted, since those stages are gated on approved hardware. Measured sizes and
quality on the 7-layer real slice are in `docs/reports/M2.md` and `docs/reports/M3.md`.
